Anatomical AR Viewer

Android tablet · Unity AR Foundation · built in one week as an interview prototype

What it does
Places a segmented CT model — skull, brain, tumour as separate meshes — on a table in front of you through the tablet camera. You can toggle each anatomical layer on and off, make layers semi-transparent to see what sits behind them, and drag a clipping plane through the model to cut a cross-section at any depth.
Why
A flat screen shows one slice at a time. Anatomy is spatial, and the relationship between a tumour and the structures around it is the thing a surgeon or a student actually needs to read. Holding the model at real scale and cutting through it answers that directly.
What I built
  • Mesh preparation in Blender — decimation and retopology so the geometry renders in real time on a tablet, split per structure for independent control
  • Layer visibility and per-layer transparency, driven from a runtime UI
  • Clipping plane as a shader-level world-space cut, so the cross-section stays correct as the model is moved
  • Marker-based placement and anchoring through AR Foundation; tested on Samsung Galaxy Tab

Teleoperated AGV Simulator

Unity · WebRTC + WebSocket · two devices on one network

What it does
A simulated automated guided vehicle drives through a warehouse scene in Unity. Its camera feed streams to a second device, which sends steering commands back and displays live telemetry — speed, heading, battery, and the measured round-trip latency on screen.
Why
Remote operation of a vehicle is a latency problem before it is anything else. The operator is steering against a picture that is already out of date, so the first thing worth building is the measurement — how stale the frame in front of you is, shown next to the frame itself.
What I built
  • Vehicle controller and warehouse scene in Unity, with a camera rendered to texture for streaming
  • Video over WebRTC — UDP, so a late frame is dropped rather than queued, which is the right trade for a live view
  • Telemetry and control over WebSocket, where ordering and delivery do matter
  • Round-trip latency measured by timestamping frames at capture and comparing on arrival, displayed as an overlay

Live LiDAR in a Headset

Master's thesis, Fraunhofer IPM · Godot XR + native C++/CUDA · 2024–25

What it does
An operator carries a handheld LiDAR scanner and wears an XR headset. The point cloud builds up around them as they walk, at real scale and in real time, so a gap in coverage is visible while they are still standing there instead of on a desktop afterwards.
Why
The scanner produces up to 5.2 million points per second. The existing viewer loaded finished files and indexed about 1.8 million points per second on the CPU — fine for a dataset that has stopped growing, far too slow for a stream that never stops. Without real-time indexing there is no live view, and without a live view you only find out what you missed after the scan.
What I built
  • Godot XR application subscribing to the scanner's ROS topic and feeding points in as they arrive
  • Restructured an existing GPU octree indexer from fixed-file input to a continuous, open-ended stream, batching roughly 100k points per call
  • Native C++/CUDA module called across a DLL boundary: points marshalled in each frame, the frustum-culled visible set returned for rendering
  • Python tool reproducing the sensor's output format and timing, so development and regression testing ran without the hardware connected
  • Indexing throughput rose from ~1.8M to ~300M points per second on an RTX 3060; adopted by the project team
